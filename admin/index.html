처음 구성하는 순서

  1. 프로젝트 만들기조직(회사 도메인) 확인. 프로젝트 ID는 변경 불가
  2. API 사용 설정Discovery Engine API, Agent Platform API
  3. 구독 · 앱 만들기에디션·좌석 수, 앱 이름과 위치
  4. ID 공급자Google ID 또는 타사 IdP
  5. IAM 권한관리자 역할 3개, 사용자 그룹 역할 3개
  6. 라이선스 할당자동 또는 수동
  7. 앱 구성어시스턴트, 기능 관리, 관측 가능성
  8. 데이터 연결Workspace, Microsoft, 서드파티
  9. 사용자 안내웹 앱·모바일 앱 링크 배포

세종은 이미 앱이 있으므로 각 단계를 어디서 확인하는지 위주로 봅니다.

IAM 및 관리자 › 프로젝트 만들기 / API 및 서비스 › 라이브러리

  • API 두 개를 사용 설정합니다: Discovery Engine API(검색·앱 구성), Agent Platform API(에이전트·모델, 구 Vertex AI API).

Gemini Enterprise › 구독 관리
  • 결제 계정에 연결된 구독 목록: 이름, 좌석 수, 유형(Standard/Plus), 상태, 갱신일
  • 결제 계정 관리자 역할이 있어야 보입니다.
  • 상태: 시작 전(할당 가능, 사용 불가) → 활성 → 비활성화 중(1주 유예) → 만료(사용 중단)

갱신일을 IT 일정에 등록해 두십시오.

0-6

라이선스 할당

Gemini Enterprise › 사용자 관리 › 멀티 리전 선택
  • 자동: 라이선스 자동 할당을 체크하면, GE 사용자 역할이 있는 사람이 웹 앱에 처음 접속할 때 할당됩니다. 접속하지 않으면 할당되지 않습니다.
  • 수동: 자동 할당을 끄고 사용자 추가에서 이메일을 입력합니다. 로그인 이메일과 정확히 같아야 합니다.
  • 퇴사자는 할당 해제 및 삭제로 회수합니다.
  • 사용자는 라이선스와 GE 사용자 역할이 모두 있어야 웹 앱을 쓸 수 있습니다.

ID 공급자

앱 › 개요 › ID 설정 / 설정 › 인증
  • Google ID(Workspace·Cloud ID): Drive·Gmail·Calendar 연결에 필요합니다.
  • 타사 ID 공급자(Entra ID, AD FS, Okta 등): SharePoint·OneDrive 내용을 수집하려면 필요합니다.
  • 위치(리전)마다 한 가지만 설정합니다.

나중에 바꾸면 모든 사용자의 대화 기록이 사라지고, 수집형 데이터 스토어를 다시 만들어야 합니다.

앱 만들기와 사용자 안내 주소

Gemini Enterprise › 앱 › 만들기 / 앱 › 개요 / 앱 › 통합
  • 앱 이름, 위치(global / us / eu), 고급 옵션의 회사 이름을 정합니다. 앱 ID와 위치는 만든 뒤 바꿀 수 없습니다.
  • global은 새 기능이 먼저 오지만 CMEK·Model Armor·Access Transparency를 쓸 수 없습니다. 한국 리전은 없습니다.
  • 사용자에게는 개요 또는 통합 › 웹 앱의 웹 앱 링크를 배포합니다. 개요 하단에 모바일 앱 링크도 있습니다.
  • 통합 › 웹 앱에서 인터페이스 언어를 한국어로 지정할 수 있습니다.

2-2

방법 1 · 사용자 CSV + 엑셀 (바로 가능)

  1. 매핑 시트: email · 구분 · 부서_팀
  2. 사용자 CSV 시트에 아래 수식 열 추가
  3. 피벗: 행 = 구분, 부서_팀 / 값 = 개수, 활성 합계 → 활성률
  4. 미매핑 계정은 퇴사자·외부 계정 → 라이선스 회수 검토
F2 부서_팀  =XLOOKUP(LOWER(A2), LOWER(매핑!A:A), 매핑!C:C, "미매핑")
G2 구분     =XLOOKUP(LOWER(A2), LOWER(매핑!A:A), 매핑!B:B, "미매핑")
H2 9월활성  =IF(AND(E2="ASSIGNED", D2>=DATE(2026,9,1)), 1, 0)

last_login_time은 UTC입니다. 월 경계를 엄밀히 맞추려면 9시간을 더해 비교하십시오.

2-3

방법 2 · 로그 → BigQuery (매달 자동 집계)

  1. 1장의 관측 설정(추적·로그)을 켭니다.
  2. Logging › 로그 라우터 › 싱크 만들기 → 대상 BigQuery, 아래 필터로 사용자 활동 로그만 보냅니다.
  3. 조직 매핑표를 BigQuery 테이블로 올립니다.
  4. 이메일로 결합해 월별·팀별 활성 사용자와 요청 수를 집계하고, 필요하면 Data Studio(구 Looker Studio)로 연결합니다.
logName="projects/PROJECT_ID/logs/discoveryengine.googleapis.com%2Fgemini_enterprise_user_activity"
-- 필드 경로는 실제 테이블 스키마에서 확인
SELECT m.구분, m.부서_팀,
  COUNT(DISTINCT LOWER(a.jsonPayload.useriamprincipal)) AS active_users,
  COUNT(*) AS requests
FROM `PROJECT_ID.ge_logs.discoveryengine_googleapis_com_gemini_enterprise_user_activity` a
JOIN `PROJECT_ID.sejong_ops.org_map` m
  ON LOWER(a.jsonPayload.useriamprincipal) = LOWER(m.email)
WHERE DATE(a.timestamp, "Asia/Seoul") BETWEEN "2026-09-01" AND "2026-09-30"
GROUP BY 1, 2 ORDER BY 1, active_users DESC;

통계 목적이면 질문 원문이 없는 활동 로그만 보내십시오. 로그는 보내기 시작한 날부터 쌓입니다.

실습 B엑셀로 부서별 활성률시연 + 과제4분
  1. 실습 A의 CSV에 매핑표를 붙여 방법 1을 따라 합니다.
  2. 시간이 부족하면 강사 시연 후 매핑표 양식을 받아 과제로 진행합니다.

등록과 공유 (GE 관리자)

앱 › 에이전트
  1. 에이전트 추가 › Agent Runtime을 통한 커스텀 에이전트: 이름, 설명, 리소스 경로 projects/…/reasoningEngines/RESOURCE_ID 입력. Gemini는 설명을 보고 언제 이 에이전트를 부를지 정합니다.
  2. 위치 규칙: 앱이 global이면 모든 리전, us면 us-*, eu면 europe-*만 가능. 다르면 등록 오류.

  5. 모니터링: 관측 설정을 켜면 Agent Platform › Agents › Deployments › Traces에서 요청별 시간·도구·토큰 확인.

6-2

보안 구성

  • 앱 단위 접근 제어: 기본은 프로젝트 단위 권한이라 URL만 알면 다른 팀 앱에 접속됩니다. 설정 › 리소스 접근 제어로 앱·데이터 스토어별 권한을 줍니다.
  • VPC 서비스 제어: 사무실 IP 대역에서만 접근하도록 제한합니다. Google 검색 웹 그라운딩을 켜면 적용되지 않습니다.
  • Model Armor: 실패 모드 FAIL_CLOSED 유지, 템플릿의 Cloud Logging은 끕니다. ADK·A2A 에이전트는 코드에서 따로 구성합니다.
