관리자 기본: Gemini Enterprise 관리자 설정

25분 · 00:00

관리자가 보는 화면은 두 곳입니다. 설정·통계·비용은 Google Cloud 콘솔에서, 사용자 경험 확인과 에이전트 만들기는 Gemini Enterprise 웹 앱에서 합니다. 이 장에서는 처음 구성하는 순서와 앱 설정 화면 전체를 한 번 훑습니다.

처음 구성하는 순서

Google 공식 문서의 준비 순서입니다. 세종은 이미 앱이 있으므로 각 단계가 어디에서 확인되는지 위주로 봅니다.

구독과 라이선스

  • 구독 만들기: Manage subscriptions › Create subscription → 에디션(Standard / Plus)에서 Subscribe → 결제 계정, 구독 이름, 라이선스 수, 기간(월·연), 자동 갱신 → 프로젝트와 위치 유형 선택 → Create.
  • 구독 상태: 시작 전(할당은 가능, 사용은 불가) → 활성 → 비활성화 중(1주 유예) → 만료(사용 중단). 갱신 일정을 달력에 넣어 두십시오.
  • 라이선스 할당: Manage users › 멀티 리전 선택 › Add users에서 이메일 입력 후 구독 선택. 사용자가 로그인하는 이메일과 정확히 같아야 합니다.
  • 자동 할당: Assign licenses automatically를 켜면 라이선스 없는 사용자가 처음 로그인할 때 자동으로 받습니다. 풀이 비면 "접근 권한 없음"이 뜹니다.
  • 사용자가 웹 앱을 쓰려면 라이선스와 Gemini Enterprise 사용자 역할이 모두 있어야 합니다. 역할은 개인이 아니라 Google 그룹(예: ge-users@)에 부여합니다.

출처: Manage subscriptions and licenses · Access control

ID 공급자

Google ID

Google Workspace 계정으로 로그인합니다. Google이 신규 구성에 권장하며, Drive·Gmail·Calendar를 데이터 소스로 쓰려면 필수입니다. 외부 IdP로 SSO(SAML)를 붙일 수 있습니다.

Workforce Identity Federation

Entra ID·Okta 계정으로 직접 로그인합니다. SharePoint·OneDrive·Outlook 내용을 수집하려면 필수입니다. google.subject를 소문자 이메일로 매핑하고, 그룹 조회를 위해 SCIM을 설정합니다.

경로: Settings › Authentication › Add identity provider → 유형 선택 → Save changes. 위치당 한 가지 유형만 쓸 수 있고, 나중에 바꾸면 사용자 대화 기록이 사라집니다 (6장).

출처: Configure identity provider

앱과 웹 앱 주소

  1. Gemini Enterprise › Apps › Create app: 앱 이름, 위치(global / us / eu), 고급 옵션의 회사 이름(모델이 회사를 알아보게 돕는 이름). 앱 ID와 위치는 만든 뒤 바꿀 수 없습니다. 에디션은 앱이 아니라 구독에서 정해집니다.
  2. 사용자에게 줄 주소: 앱 › Integration에서 Enable the Web App이 켜져 있는지 확인하고 The link to your web app을 복사합니다. 사내 포털·즐겨찾기로 배포합니다.
  3. 고급 옵션의 Include cross-domain documents는 프롬프트 주입 위험이 있어 끄는 것을 권장합니다.

데이터 소스 연결

  1. Data stores › Create data store → 소스 선택(Drive, Gmail, Calendar, Cloud Storage, BigQuery, SharePoint 등) → 멀티 리전 → 커넥터 이름 → Create. 상태가 Active가 될 때까지 기다립니다.
  2. 앱에 붙이기: Apps › 앱 › Connected data sources › Add existing data stores → 선택 → Connect.
  3. 사용자는 웹 앱의 Manage your data › Authorize에서 한 번 로그인해 연결을 승인합니다.
Drive를 연결하려면Workspace 관리 콘솔에서 "Workspace의 스마트 기능"과 "다른 Google 제품의 스마트 기능"이 켜져 있어야 합니다. Drive는 원본을 복사하지 않고 질문할 때마다 조회하는 방식(페더레이션)이어서 원본 권한이 그대로 적용됩니다.

조회 방법과 읽을 때 주의할 점

  1. 탭을 고른 뒤 날짜 범위를 정하고 필터를 설정한 다음 Refresh를 누릅니다. 월 단위 지표는 달력 월 기준입니다.
  2. 데이터는 약 6시간마다 갱신됩니다. 오늘 오전 사용량이 바로 보이지 않는 것은 정상입니다.
  3. 지표는 앱에 데이터 스토어를 연결한 시점부터 쌓입니다. 데이터 스토어 연결을 해제하면 일부 지표가 사라질 수 있으니 해제 전에 내보내 두십시오.
  4. 검색 분석은 global 앱에서 정식 기능이고, US·EU 멀티 리전 앱에서는 Preview입니다.
  5. 보관·재가공이 필요하면 analytics:exportMetrics API로 BigQuery에 내보냅니다. 최근 30일분, 프로젝트당 하루 5회, 조직당 하루 25회까지 가능합니다.

지원부서·변호사 팀별 이용 통계

10분 · 00:40
먼저 알아야 할 사실Analytics 대시보드에는 부서·팀(그룹, 조직 단위) 필터가 없습니다. 팀별 통계는 사용자 단위 데이터를 세종의 조직 매핑표(이메일 → 지원부서/변호사 팀)와 결합해서 만듭니다. Google 블로그도 "대화 로그를 인사·사업부 데이터와 결합해 부서별로 분석"하는 방식을 안내합니다.

세 가지 방법 (난이도 순)

1단계 · 바로 가능

사용자 CSV + 엑셀

Export all users의 last_login_time으로 기간 내 로그인한 사람을 활성으로 봅니다. 부서별 라이선스 수·활성 인원·활성률까지 산출됩니다. 사용량(메시지 수)은 없습니다.

2단계 · 허용 요청

User Level 탭 + 매핑표

사용자별 메시지 수, 자체 에이전트 메시지 수가 나옵니다. 1인당 사용량과 에이전트 활용도를 팀별로 비교할 수 있습니다. Google 계정 팀에 허용 요청이 필요합니다.

3단계 · 상시 대시보드

로그 → BigQuery → Looker Studio

Log Router 싱크로 사용자 활동 로그를 BigQuery에 쌓고 매핑표와 JOIN합니다. 기능별(검색·어시스턴트·에이전트)·일자별 분석과 자동 갱신 대시보드가 가능합니다.

실습 B엑셀로 부서·팀별 활성률 만들기 (1단계)4분
  1. 조직 매핑표 시트를 준비합니다. 열: email · 구분(지원부서/변호사) · 부서_팀
  2. 실습 A에서 받은 CSV 시트에 열을 추가합니다. 이메일 대소문자를 맞추기 위해 LOWER를 씁니다.
엑셀 수식 (CSV 시트 F2부터 아래로)
F2  부서_팀   =XLOOKUP(LOWER(A2), LOWER(매핑!A:A), 매핑!C:C, "미매핑")
G2  구분      =XLOOKUP(LOWER(A2), LOWER(매핑!A:A), 매핑!B:B, "미매핑")
H2  9월활성   =IF(AND(E2="ASSIGNED", D2>=DATE(2026,9,1)), 1, 0)
  1. 피벗 테이블: 행 = 구분, 부서_팀 / 값 = 라이선스 수(개수), 9월활성(합계) / 활성률 = 합계 ÷ 개수
  2. 미매핑으로 나온 계정은 퇴사자·외부 계정·이메일 변경자입니다. 라이선스 회수 대상인지 함께 확인합니다.

last_login_time은 UTC입니다. 월 경계를 엄밀히 맞추려면 9시간을 더해 한국 시간으로 바꾼 뒤 비교하십시오.

3단계 구성: 로그를 BigQuery로

  1. 관측 설정에서 OpenTelemetry 추적·로그를 켭니다 (1장).
  2. Logging › Log Router › Create sink → 대상 BigQuery 데이터 세트, 아래 포함 필터를 입력합니다.
Log Router 싱크 필터 (PROJECT_ID 교체)
logName="projects/PROJECT_ID/logs/discoveryengine.googleapis.com%2Fgemini_enterprise_user_activity"
  1. 조직 매핑표를 BigQuery 테이블 sejong_ops.org_map으로 올립니다 (CSV 업로드).
  2. 아래와 같이 결합합니다. 사용자 열 이름은 싱크가 만든 테이블 스키마에서 확인하십시오. Google 블로그는 사용자 IAM 이메일 필드를 useriamprincipal로 소개합니다.
BigQuery SQL 예시 — 월별 팀별 활성 사용자와 요청 수
-- 테이블·필드 경로는 실제 스키마에 맞게 수정
WITH act AS (
  SELECT
    LOWER(jsonPayload.useriamprincipal) AS email,
    DATE(timestamp, "Asia/Seoul")       AS d
  FROM `PROJECT_ID.ge_logs.discoveryengine_googleapis_com_gemini_enterprise_user_activity`
  WHERE DATE(timestamp, "Asia/Seoul") BETWEEN "2026-09-01" AND "2026-09-30"
)
SELECT
  m.`구분`, m.`부서_팀`,
  COUNT(DISTINCT a.email) AS active_users,
  COUNT(*)                AS requests,
  ROUND(COUNT(*) / COUNT(DISTINCT a.email), 1) AS req_per_user
FROM act a
JOIN `PROJECT_ID.sejong_ops.org_map` m ON a.email = LOWER(m.email)
GROUP BY 1, 2
ORDER BY 1, active_users DESC;
보안 포인트사용자 활동 로그 테이블에는 질문 원문이 없고(<elided>), 프롬프트 로깅을 켠 경우에만 gen_ai.user.message·gen_ai.choice 테이블에 원문이 쌓입니다. 통계 목적이면 활동 로그만 싱크하십시오. BigQuery 데이터 세트 위치는 앱 위치에 맞춥니다 (global·US 앱 → US, EU 앱 → EU).

  3. 리소스 경로 projects/PROJECT_ID/locations/LOCATION/reasoningEngines/RESOURCE_ID 입력 후 Create.
