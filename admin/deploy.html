세종 교육 자료 · 웹 게시

교육 페이지 웹 게시 방법

세종 교육 자료(사용자 교재, 실습 가이드북, 관리자 교육)를 GitHub Pages로 인터넷에 올리는 순서입니다. 처음 한 번만 Pages를 켜면, 이후에는 파일을 바꾸고 푸시하는 것만으로 사이트가 갱신됩니다.

저장소 github.com/rmadudtjr1/sejong_lab로컬 폴더 C:\Megazone\교육 자료\sejong\sejong_lab_upload기준 GitHub Docs, 2026-10
01

준비물

항목확인 방법
Git 설치명령 프롬프트에서 git --version이 버전을 출력하면 됩니다. 없으면 git-scm.com에서 설치합니다.
GitHub 계정과 저장소 쓰기 권한저장소 Settings › Collaborators에 계정이 있어야 푸시할 수 있습니다. Pages 설정은 관리자(admin) 권한이 필요합니다.
로컬 저장소sejong_lab_upload 폴더 안에 .git 폴더가 있으면 이미 연결되어 있습니다. 새 PC라면 git clone https://github.com/rmadudtjr1/sejong_lab.git
공개 범위GitHub Pages 사이트는 저장소가 비공개여도 인터넷에 공개됩니다. 의뢰인 정보, 실제 사건, 내부 설정값(프로젝트 ID, 결제 계정 등)은 올리기 전에 반드시 빼십시오. 무료 요금제는 공개 저장소에서만 Pages를 쓸 수 있습니다.

출처: GitHub Docs · Configuring a publishing source

02

파일 넣기

폴더 구조가 곧 웹 주소입니다. index.html이라는 이름의 파일은 폴더 주소만으로 열립니다.

폴더 안 위치웹 주소내용
index.html…github.io/sejong_lab/사용자 교재
SEJONG_index.html…github.io/sejong_lab/SEJONG_index.html실습 가이드북
admin/index.html…github.io/sejong_lab/admin/관리자 교육
admin/slides.html + slides-img/…github.io/sejong_lab/admin/slides.html관리자 교육 발표 슬라이드 (이미지 폴더 함께 커밋)
admin/deploy.html…github.io/sejong_lab/admin/deploy.html이 문서
  • .nojekyll 빈 파일은 지우지 마십시오. GitHub의 Jekyll 변환을 끄고 파일을 그대로 게시하게 합니다.
  • 웹 주소는 대소문자를 구분합니다. 폴더·파일 이름은 영문 소문자를 권장합니다.
03

커밋과 푸시

명령 프롬프트(또는 PowerShell)를 열고 아래를 순서대로 실행합니다.

명령 프롬프트
cd "C:\Megazone\교육 자료\sejong\sejong_lab_upload"
git status                      # 바뀐 파일 확인
git add admin/index.html README.md
git commit -m "관리자 교육 페이지 추가"
git push origin main
  • git status에 ahead 3처럼 나오면 아직 올리지 않은 커밋이 3개라는 뜻입니다. git push 한 번에 모두 올라갑니다.
  • 처음 푸시할 때 GitHub 로그인 창이 뜨면 브라우저로 로그인합니다. Windows는 자격 증명 관리자가 기억합니다.
04

Pages 켜기 (최초 1회)

이미 켜져 있으면 건너뜁니다. 저장소 관리자 권한이 필요합니다.

  1. github.com/rmadudtjr1/sejong_lab 에서 Settings 탭을 엽니다.
  2. 왼쪽 메뉴 "Code and automation"(또는 "Code, planning, and automation") 아래 Pages를 누릅니다.
  3. Build and deployment › Source를 Deploy from a branch로 둡니다.
  4. Branch를 main, 폴더를 / (root)로 고르고 Save를 누릅니다.
  5. 잠시 뒤 같은 화면 위쪽에 "Your site is live at https://rmadudtjr1.github.io/sejong_lab/"가 표시됩니다.
05

게시 확인

  1. 저장소의 Actions 탭에서 pages build and deployment 작업이 초록색 체크로 끝났는지 봅니다. 보통 1~2분 걸립니다.
  2. 브라우저에서 https://rmadudtjr1.github.io/sejong_lab/admin/ 를 엽니다.
  3. 예전 화면이 보이면 Ctrl+F5로 새로 고침합니다 (브라우저 캐시).
  4. 휴대폰에서도 한 번 열어 목차와 표가 잘 보이는지 확인합니다.
06

수정본 올리기

  1. 수정한 HTML을 같은 이름으로 sejong_lab_upload 안 같은 위치에 덮어씁니다. (관리자 교육 원본: sejong\admin\index.html → sejong_lab_upload\admin\index.html)
  2. 3장 명령을 다시 실행합니다. 커밋 메시지는 바뀐 내용을 한 줄로 씁니다.
  3. 5장 순서로 확인합니다. Pages 설정은 다시 할 필요가 없습니다.
07

문제 해결

증상원인해결
Unable to create '…/.git/index.lock': File exists이전 git 작업이 남긴 잠금 파일다른 git 창이 없는지 확인한 뒤 .git 폴더의 해당 .lock 파일 삭제 후 다시 실행. stale-로 시작하는 파일은 지워도 됩니다.
rejected … (fetch first)다른 사람이 먼저 푸시함git pull --rebase origin main 후 다시 git push origin main
403 / Permission denied저장소 쓰기 권한 없음, 다른 계정으로 로그인됨저장소 관리자에게 Collaborator 추가 요청, Windows 자격 증명 관리자에서 github.com 항목 삭제 후 재로그인
주소가 404Pages 꺼짐, 배포 진행 중, 경로 대소문자 오류4장 설정 확인, Actions 완료 대기, 주소 철자 확인
